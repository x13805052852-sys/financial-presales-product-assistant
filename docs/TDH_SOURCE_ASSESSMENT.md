## 不进入首版默认知识库

### 独立证据库（51 个）

以下资料可以保留，但只能在用户明确询问“是否兼容、是否有证书、是否有测试证明”时检索：

- `兼容性认证/` 下的操作系统、硬件、存储、云平台、应用和 KUNPENG NATIVE 证书；
- `软件安全与代码自主率/` 下的检测、渗透和自主率报告；
- `性能/` 下的 TPC-DS 报告；
- 9.0 目录下的盖章软件测评报告。

原因：这些文件回答的是举证问题，不是“哪个产品能实现哪个功能”。其中大量证书对应 TDH 4.x～7.x，若与 9.5 产品推荐混检，容易把历史兼容关系说成当前承诺。证据回答必须同时展示产品版本、第三方产品版本、报告日期和来源。

### 测试资料库（1 个）

`TDH标准测试案例202502-TDH9.3（更新中）.docx` 可用于生成 POC 和验收问题，但文件仍标注“更新中”且基于 TDH 9.3，不应作为销售答案的权威事实源。

### 二期技术库（17 个）

- TDH 9.5 的组件、安装和运维手册；
- Inceptor 优化、弹性计算、Kafka 不停机扩容等实践资料。

这些资料适合回答组件细节、实施和排障追问，不属于首版产品匹配。9.5 手册所在目录已明确注明“Word 版本不保证质量”，应优先替换为正式 PDF 或官方文档快照，并在产品专家复核后启用。

## 首版应建立的 TDH 产品映射

根据核心资料，知识库不能只标记“TDH”，至少要拆到售卖 Edition，并明确与 ArgoDB/TDC 的边界：

| 客户需求或功能 | 首选候选 | 必须追问/限制 |
| --- | --- | --- |
| 大规模离线批处理、数据湖底座、多类型数据统一存储 | TDH 数据湖版 | 数据规模、并发、实时性、是否已有 Hadoop/CDH |
| 高并发交互分析、数据集市、OLAP | TDH 集市版 | 并发量、响应时间、数据更新频率；强实时需比较 ArgoDB AP |
| 数据湖与数仓统一、减少多份数据复制 | TDH 湖仓版 | 是否需要同一份数据兼顾湖与仓、原平台迁移约束 |
| 批流一体、实时入湖、T+1 分钟级分析 | TDH 湖仓集一体版 | 写入时延、查询 SLA、是否需要实时事务或增量计算 |
| 高性能实时数仓/数集、持续增量计算 | ArgoDB AP（跨产品候选） | 不应仅因资料位于 TDH 文件夹就推荐 TDH |
| 事务与分析混合、TP+AP | ArgoDB HTAP（跨产品候选） | 事务一致性、并发和数据库替代范围 |
| 多集群统一管理、跨集群资源调度、云原生数据服务 | TDC（跨产品候选） | 这是平台管理能力，不能误归为 TDH Edition |

“数据工程版”在售卖资料中被标为不建议新项目优先推荐，首版机器人应将它设为低优先级，仅在存量客户或明确预算/兼容约束下提示，并要求人工确认。
