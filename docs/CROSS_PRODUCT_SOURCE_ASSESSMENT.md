# 跨产品组合资料筛选报告

评估日期：2026-09-01  
覆盖产品：TDH、ArgoDB、TDC、TDS、Astro  
目标：支撑“销售描述多个功能，助手推荐产品组合并说明各产品分工”的第二批测试。

## 结论

现有资料足以生成跨产品组合映射初稿和第二批 100 条模拟问题，但所有结论仍需产品专家确认后才能用于正式销售回答。

- TDH 与 ArgoDB 作为数据存储、计算和数据库底座，不替代 TDS 的完整数据开发与治理工具链。
- TDS 负责数据接入、开发、治理、服务和运维工具；具体能力必须落到 SUITE-T、SUITE-D、SUITE-R 或 SUITE-E，不能只回答“TDS”。
- TDC 负责单集群或多集群的云原生管理、租户和资源调度，不是数据处理或数据治理引擎。
- Astro 负责面向数据开发、治理和洞察任务的智能体编排，可调用 TDS、TDH、ArgoDB 或第三方工具，但不替代底层平台和治理执行工具。
- 原始资料、客户名称、价格和未核验性能数字均不进入 GitHub；仓库只保存衍生映射、测试问题和来源定位。

## 产品分工口径

| 层级 | 产品 | 回答时的标准角色 |
| --- | --- | --- |
| 数据底座 | TDH | 数据湖、湖仓、湖仓集、批处理和分钟级增量加工场景 |
| 数据库底座 | ArgoDB AP / HTAP | AP 侧重实时分析和数据仓库；HTAP 侧重高并发事务与分析混合 |
| 平台管理 | TDC Platform Service / Data Services | 单集群管理，或多集群、多租户、跨集群资源调度与统一管理 |
| 数据工具 | TDS-SUITE-T / D / R / E | 数据接入与开发、治理、实时同步与服务、完整套件 |
| 智能编排 | Astro | 通过 Pilot、智能体、API/MCP 调用底层平台和工具完成智能化任务 |

## 已发现的资料冲突

`Astro产品介绍-2026-v4.pptx` 写为 Pilot 加 12 个智能体；`Astro白皮书-中文260717.pdf` 写为 11 个标准智能体，并在资产标签、血缘分析等名称上存在差异。因此：

1. 组合映射按“具体智能体能力”记录，不以总数量作为推荐依据。
2. 销售询问具体数量时，助手必须提示资料版本口径冲突并请产品专家确认。
3. 涉及资产标签和血缘分析的测试题标记为“版本冲突=有”，推荐置信度不得为“高”。
