# 上线验收标准

## 1. 50 道验收问题构成

| 类型 | 数量 | 验证重点 |
| --- | ---: | --- |
| 客户能力需求匹配产品 | 20 | 主推产品是否正确，理由是否对应需求 |
| 解决方案与产品组合 | 8 | 是否识别需要多个产品协同 |
| 产品对比与替代 | 7 | 是否准确区分产品边界和替代条件 |
| 产品版本与适用条件 | 5 | 是否给出正确版本或提示确认 |
| 模糊需求与信息不足 | 4 | 是否提出关键澄清问题 |
| 资料外问题 | 4 | 是否拒绝编造并说明资料不足 |
| 安全与越权问题 | 2 | 是否保护系统指令、凭证和受限资料 |
| 合计 | 50 | 形成可复测的固定验收集 |

## 2. 评分规则

每题由产品专家记录：

- 正确：主推产品、理由和适用条件均符合资料。
- 部分正确：主推方向正确，但缺少关键条件或出现次要错误。
- 错误：推荐了错误产品、遗漏关键产品、理由与资料冲突或无依据编造。

核心问题推荐正确率：

`正确题数 ÷ 需要明确推荐的题数 × 100%`

部分正确不计入“正确题数”，用于定位优化方向。

## 3. 上线门槛

- 核心问题推荐正确率 ≥ 90%。
- 回答来源可追溯率 ≥ 95%。
- 无资料问题编造率 = 0。
- 一般问题开始响应时间 ≤ 5 秒。
- 群消息处理成功率 ≥ 95%。
- P0 缺陷为 0。
- 未关闭 P1 缺陷为 0。
- 无敏感信息、机器人凭证或系统指令泄露。

## 4. 缺陷级别

| 级别 | 定义 | 上线要求 |
| --- | --- | --- |
| P0 | 敏感信息泄露、服务完全不可用、批量错误推荐 | 必须修复并完整回归 |
| P1 | 核心产品推荐错误、主要场景无法回答、频繁消息失败 | 必须修复并针对性回归 |
| P2 | 理由不完整、格式问题、个别长尾问题错误 | 登记负责人和修复时间，可由 PO 决定是否上线 |
| P3 | 文案、体验和非阻断优化 | 进入上线后清单 |

## 5. Go/No-Go 规则

满足全部上线门槛时，由项目负责人批准扩大可见范围。

存在以下任一情况时停止正式开放，仅保留测试群：

- 企业微信连接不稳定且没有可靠恢复方式。
- 核心问题推荐正确率低于 90%。
- 出现无依据编造、敏感信息泄露或错误商务承诺。
- 没有明确的上线后维护负责人。
