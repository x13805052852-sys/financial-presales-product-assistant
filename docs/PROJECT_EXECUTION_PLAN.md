# 五天内部执行计划

## 使用方式

- 每项任务使用唯一编号跟踪。
- 每天开始时确认负责人，结束时按验收条件关闭任务。
- 未达到验收条件的任务不得标记完成。
- P0 阻断问题立即处理；新增功能需求统一进入上线后清单。

角色缩写：项目负责人（PO）、产品专家（SME）、AI/后端开发（DEV）、企业微信管理员（ADMIN）、销售测试用户（UAT）。

## 第 1 天：范围、资料与接入条件

目标：当天结束前冻结首版范围，并确认资料、人员和企业微信能力全部可用。

| 编号 | 任务 | 负责人 | 依赖 | 产出与验收 |
| --- | --- | --- | --- | --- |
| D1-01 | 召开 30 分钟启动会 | PO | 无 | 明确目标、角色、时间点和上线范围 |
| D1-02 | 确定首批 5～8 组产品线 | PO + SME | D1-01 | 每组产品至少有有效资料和两条测试需求 |
| D1-03 | 收集产品方案总表原始 Excel | SME | D1-01 | 文件可读取，包含完整字段而非截图 |
| D1-04 | 建立资料清单 | SME | D1-02 | 每份资料记录产品、版本、日期、保密级别和审核状态 |
| D1-05 | 标记重复、过期和冲突资料 | SME | D1-04 | 每个冲突有明确采用版本和理由 |
| D1-06 | 建立产品标准名及别名表 | SME | D1-03 | TDH、TDC、ArgoDB 等名称能够唯一归一 |
| D1-07 | 建立能力—产品映射初稿 | SME | D1-02、D1-06 | 每个首批产品至少有两条能力映射和推荐理由 |
| D1-08 | 收集 30 条真实销售需求 | UAT + SME | D1-02 | 每条包含预期产品、理由和确认人 |
| D1-09 | 创建 API 模式智能机器人 | ADMIN | D1-01 | 获得 BotID、Secret，设置正确可见范围 |
| D1-10 | 创建内部测试群并加入机器人 | ADMIN | D1-09 | 指定成员能够 @机器人 |
| D1-11 | 验证长连接和凭证 | DEV + ADMIN | D1-09 | 服务能够建立连接并收发测试消息 |
| D1-12 | 范围冻结评审 | PO | D1-02 至 D1-11 | 发布首版范围清单；新增内容进入后续清单 |

当日阻断条件：无法获得机器人 API 权限、没有可用模型/知识库环境、没有产品专家确认口径、首批产品缺少有效资料。

## 第 2 天：知识库与产品匹配规则

目标：形成可检索、可追溯的知识库 V1，并通过离线检索测试。

| 编号 | 任务 | 负责人 | 依赖 | 产出与验收 |
| --- | --- | --- | --- | --- |
| D2-01 | 将 Excel、PPT、PDF 转换为可处理文本 | DEV | D1-04 | 内容完整，标题和表格关系未丢失 |
| D2-02 | 删除重复、过期和禁止使用内容 | SME + DEV | D2-01、D1-05 | 知识库仅保留允许使用的有效资料 |
| D2-03 | 按产品、方案、场景、版本组织资料 | DEV | D2-02 | 每段内容均能关联产品与来源 |
| D2-04 | 添加来源元数据 | DEV | D2-03 | 包含文件名、版本、日期、页码或表格行号 |
| D2-05 | 配置文档切分和知识索引 | DEV | D2-04 | 表格关系、产品组合和限制条件可被检索 |
| D2-06 | 配置检索与结果重排 | DEV | D2-05 | 相关产品资料优先于名称相似但场景无关的资料 |
| D2-07 | 配置回答模板 | DEV + SME | D1-07 | 输出包含推荐、理由、条件、备选和来源 |
| D2-08 | 配置无答案与冲突处理规则 | DEV + SME | D2-07 | 无证据不推荐；冲突时提示版本差异 |
| D2-09 | 使用 30 条需求完成离线检索测试 | DEV + SME | D2-06、D1-08 | 至少 80% 的需求检索到正确资料 |
| D2-10 | 修正知识库并发布 V1 | DEV | D2-09 | 阻断性检索错误关闭，版本可回滚 |

| 编号 | 任务 | 负责人 | 依赖 | 产出与验收 |
| --- | --- | --- | --- | --- |
| D3-01 | 实现需求要素提取 | DEV | D2-10 | 能识别目标能力、现有系统和主要限制条件 |
| D3-02 | 实现知识检索与产品候选排序 | DEV | D3-01 | 推荐只基于已审核知识和映射规则 |
| D3-03 | 实现结构化答案生成 | DEV | D3-02 | 答案符合六段回答规范并带来源 |
| D3-04 | 实现企业微信消息接收 | DEV | D1-11 | 能处理群内 @机器人文本消息 |
| D3-05 | 实现流式回复或处理中状态 | DEV | D3-04 | 用户能在 5 秒内看到响应开始 |
| D3-06 | 实现短上下文追问 | DEV | D3-04 | 能理解与当前需求直接相关的后续问题 |
| D3-07 | 实现超时、重试和错误提示 | DEV | D3-04 | 外部服务失败时不静默、不重复发送 |
| D3-08 | 配置凭证安全和脱敏日志 | DEV + ADMIN | D3-04 | 日志不出现 Secret 和受限资料正文 |
| D3-09 | 完成 20 轮群内问答 | UAT + DEV | D3-03 至 D3-08 | 消息链路稳定，问题均有结果或明确提示 |
| D3-10 | 完成内部演示和问题登记 | PO | D3-09 | 演示版本 V0.9 可供第 4 天验收 |

## 第 4 天：业务验收与发布准备

目标：完成 50 道验收测试、安全检查和上线准备，形成发布候选版。

| 编号 | 任务 | 负责人 | 依赖 | 产出与验收 |
| --- | --- | --- | --- | --- |
| D4-01 | 将测试集扩充至 50 道 | SME + UAT | D1-08 | 覆盖七类测试场景，预期答案已确认 |
| D4-02 | 执行功能验收测试 | UAT | D3-10、D4-01 | 每题记录推荐正确性、理由、来源和耗时 |
| D4-03 | 产品专家逐题复核 | SME | D4-02 | 每题标记正确、部分正确或错误并说明原因 |
| D4-04 | 修正错误知识和映射关系 | DEV + SME | D4-03 | P0/P1 内容问题全部关闭 |
| D4-05 | 修正检索、提示词和回答格式 | DEV | D4-03 | 同类问题回归通过，不影响已通过用例 |
| D4-06 | 测试资料外、模糊和错误前提问题 | UAT | D4-01 | 能拒答或提出关键澄清问题 |
| D4-07 | 测试越权、敏感信息和提示词攻击 | DEV + SME | D3-08 | 不泄露系统指令、凭证和受限内容 |
| D4-08 | 执行完整回归测试 | DEV + UAT | D4-04 至 D4-07 | 达到验收标准中的全部上线门槛 |
| D4-09 | 准备上线、监控和回滚步骤 | DEV + ADMIN | D4-08 | 操作步骤可由非开发成员核对执行 |
| D4-10 | 编写一页式用户说明 | PO + SME | D4-08 | 包含使用方法、示例、限制和反馈入口 |
| D4-11 | 发布候选版本 V1.0 | PO | D4-08 至 D4-10 | 版本冻结，配置和知识索引已备份 |

## 上线后一周

- 每天查看错误推荐、无答案问题和高延迟请求。
- 当天修正高频且有明确资料依据的问题。
- 新资料先登记、审核，再进入知识库。
- 每日形成一次错题和资料缺口摘要。
- 一周后评估第二批产品和 CRM 等系统集成需求。
