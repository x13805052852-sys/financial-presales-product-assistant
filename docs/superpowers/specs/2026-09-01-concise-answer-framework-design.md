# 企业微信售前助手简洁回答框架设计

- 日期：2026-09-01
- 适用对象：金融售前产品匹配助手
- 适用渠道：企业微信机器人及内部测试问答
- 状态：已确认，待实施

## 1. 目标

将机器人默认回答从完整的六至七项验收结构，调整为适合企业微信阅读的三段式结构。完整字段继续保留在知识库和测试数据中，用于产品审核、来源追溯和异常处理，但不在每次回答中全部展示。

## 2. 方案比较

### 方案 A：只输出一句结论

优点是最短；缺点是产品组合稍复杂时无法说明各产品职责，容易让销售误以为其中某个产品能够独立完成全部功能。

### 方案 B：默认三段式，按需补充

默认输出“结论、推荐组合、产品分工”。只有信息不足、资料冲突、安全越界或用户主动要求详细说明时，才增加必要内容。

该方案兼顾阅读效率和产品边界准确性，确定为实施方案。

### 方案 C：每次完整输出七项

能够展示全部审核信息，但企业微信消息过长，不适合作为默认交互方式。完整七项仍保留为内部审核结构。

## 3. 默认回答结构

正常情况下只展示以下三部分：

1. **结论**：一句话回答能否实现以及推荐方向。
2. **推荐组合**：列出主推产品组合；存在明显的时效分层时，最多给出两个组合。
3. **产品分工**：用一句话或简短分项说明各产品分别负责什么。

示例：

> **结论：**Astro 可以辅助实时数据治理，但不能单独完成，需要配合数据底座和 TDS 治理工具。
>
> **推荐组合：**秒级场景使用 ArgoDB AP + TDS-SUITE-R + TDS-SUITE-D + Astro；分钟级场景使用 TDH 湖仓集一体版 + TDS-SUITE-D + Astro。
>
> **产品分工：**ArgoDB AP/TDH 负责数据处理，TDS 负责治理执行，Astro 负责智能分析与任务编排。

## 4. 按需增加的内容

以下内容不作为固定标题，只有必要时才追加：

- **需要确认**：问题信息不足且会改变推荐结果时，最多提出两个关键问题。
- **风险说明**：资料存在版本冲突、能力未经确认或用户要求越界承诺时，用一句话说明。
- **资料来源**：用户主动询问依据、进入正式方案审核或需要处理资料冲突时展示。
- **适用条件和可选方案**：条件会明显改变产品选择，或用户要求详细方案时展示。

## 5. 不同问题类型的输出规则

| 问题类型 | 默认输出 |
| --- | --- |
| 信息明确的单产品问题 | 结论；推荐组合；产品分工 |
| 信息明确的跨产品问题 | 结论；推荐组合；产品分工 |
| 信息不足问题 | 初步结论；候选组合；产品分工；需要确认 |
| 产品边界错误 | 纠正结论；正确组合；产品分工 |
| 资料冲突 | 暂定结论；产品分工；风险说明 |
| 价格、绝对性能、零停机或敏感信息 | 简短拒绝或转人工；必要的风险说明 |
| 用户要求详细说明 | 在三段式基础上展开适用条件、可选方案和资料来源 |

## 6. 数据与实现边界

- 组合映射中的适用条件、排除条件、必须追问、来源、冲突和审核状态全部保留。
- 测试题库中的完整预期字段全部保留，不因前端回答缩短而删除。
- 题库的“预期答案要点”统一生成三段式默认文案；需要追问或风险说明的题目追加相应内容。
- 企业微信渲染层默认不展示空字段，也不显示没有实际内容的标题。
- 用户在当前对话和后续测试中提出产品问题时，同样使用本设计的简洁框架。

## 7. 验收标准

1. 默认回答只包含结论、推荐组合和产品分工三个部分。
2. 信息不足时最多追加两个关键追问。
3. 不需要追问时不得机械展示“需要确认：无”。
4. 用户未要求详细说明时，不默认展开资料来源、完整适用条件和可选方案。
5. 产品分工必须保留，不能只堆叠产品名称。
6. 资料冲突和安全越界不能因回答变短而被隐藏。
7. 自动测试验证三段式标题、按需字段和问题类型之间的对应关系。
8. CSV、Excel 使用说明和仓库设计文档的口径保持一致。
