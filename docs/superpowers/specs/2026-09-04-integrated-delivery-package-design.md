# 金融售前助手整合交付包设计

日期：2026-09-04

## 目标

把当前 TDH、Ops 和无涯三类资料与知识库成果整理成一个可独立复制、查阅和验收的完整交付包。原始资料保持原有目录层级和文件内容；同时为每个分类新增以 Markdown 和 Excel 为主的知识库交付，不移动、不重命名、不改写现有源目录及此前生成的成果。

## 输出位置与命名

在本地公司资料目录新建：

`金融售前助手_整合交付包_20260904/`

同级生成压缩包：

`金融售前助手_整合交付包_20260904.zip`

如果目标名称已经存在，本次任务停止并改用带时分秒的全新名称，不合并到旧目录，也不覆盖旧文件。

## 原始文件保护

- 使用复制操作，不对三个源目录执行移动、删除、改名或内容修改。
- 复制时包含隐藏文件、视频、压缩包和已有首版资料目录，保证原目录结构不变。
- 在复制前确认目标目录不存在。
- 复制后按相对路径核对文件数量和总字节数，并对普通文件生成 SHA-256。
- `00_文件校验清单.sha256` 使用交付包内相对路径，可在其他电脑复核。
- 压缩包从已经校验通过的交付目录生成，生成后执行完整性测试。

## 敏感材料与 GitHub 边界

完整本地交付包会原样包含源目录中已有的敏感压缩包、部署资料和内部材料，因此只作为受控本地交付，不上传 GitHub，不通过公开链接传播。

GitHub 只保存：

- 脱敏后的 Markdown 总览和分类说明。
- 不包含原始公司文件的知识库 Excel。
- 相对路径文件清单、生成脚本和自动测试。
- 不包含 API Key、Bot Secret、内网地址、账号密码或个人绝对路径。

## 验收标准

1. 三个源目录均在交付包中完整出现，内部相对路径保持不变。
2. 源目录与副本的文件数量、普通文件总字节数和 SHA-256 对比一致。
3. 四份新 Excel 均可打开，工作表、数据量、公式和筛选完整，无明显截断或公式错误。
4. 四份新 Markdown 能说明产品范围、知识来源、边界、风险和剩余工作。
5. ZIP 完整性检查通过，解压后顶层目录结构正确。
6. 现有源目录、现有 Excel 和仓库既有文件没有被覆盖。
7. 仓库安全扫描、Python 检查、TypeScript 类型检查和测试全部通过。

## 失败处理

- 空间不足、复制中断或校验不一致时，不生成最终 ZIP；保留日志并指出失败文件。
- 某个原始文件无法读取时，记录相对路径和错误，不用空文件替代。
- Excel 生成失败时，只重新生成对应的新文件，不修改此前版本。
- GitHub 推送前若发现敏感信息或绝对路径，先清理脱敏成果；本地完整资料包保持不变。
