# 企业微信售前助手动态回答框架设计

- 日期：2026-09-01
- 适用版本：金融售前产品助手 V0.1
- 状态：书面规格已确认，开始实施

## 1. 目标

机器人不再对所有问题强制使用“结论、推荐组合、产品分工”。系统先在本地识别问题意图，再选择对应回答框架，使产品功能介绍、方案选型和风险解释都能简洁、自然且可校验。

本次只改变回答框架选择、提示词和答案校验，不改变企业微信接入、知识检索、产品证据约束和敏感信息规则。

## 2. 方案比较

### 方案 A：模型自行决定标题

只在提示词中列出可选格式，由 GLM 自己判断。改动最少，但模型可能选错模板，程序也难以确定应校验哪些标题。

### 方案 B：额外调用一次模型分类

先调用 GLM 判断问题类型，再调用 GLM 生成答案。语义识别较灵活，但每个问题增加一次模型调用，延迟和费用增加，并扩大模型服务异常的影响。

### 方案 C：本地确定性分类后生成

程序依据明确的中文意图词在本地选择框架，再把框架传给提示词和校验器。无额外模型调用，分类结果可测试、可审计；无法明确判断时回退到产品选型框架。

确定采用方案 C。

## 3. 回答框架

### 3.1 产品功能介绍

适用于“主要功能有哪些”“产品介绍”“当前能力”“更新了什么”等问题。

必填标题：

1. `结论`
2. `主要功能`

按需标题：

- `口径说明`：资料版本、功能清单或名称存在冲突时使用。
- `需要确认`：只有缺少目标版本且版本差异会改变答案时使用，最多两个问题。

禁止机械输出 `推荐组合` 和 `产品分工`。如果知识证据没有新旧版本对比，只能说明“当前资料中的主要功能”，不得把功能描述成确定的新增项。

### 3.2 产品选型与能力边界

适用于“怎么搭配”“推荐哪个产品”“哪些产品能实现”“某产品能否单独实现”等问题，也是无法可靠分类时的默认框架。

必填标题：

1. `结论`
2. `推荐组合`
3. `产品分工`

按需标题：`需要确认`、`风险说明`、`资料来源`。风险说明只能出现一次；只有会改变推荐结果时才追问，最多两个问题。

### 3.3 风险与资料冲突解释

适用于“详细说明风险”“资料为什么不一致”“冲突是什么”“销售应如何表述”等问题。

必填标题：

1. `冲突点`
2. `实际影响`
3. `销售口径`

不再重复输出选型组合。销售口径必须区分“已明确的具体能力”和“待确认的数量、名称、版本或交付范围”，不得因为清单冲突直接否定已有资料明确描述的能力。

## 4. 意图分类规则

分类在调用模型前完成，不使用外部模型：

1. 包含“风险、冲突、不一致、口径、详细说明风险、为什么不一致”等表达，优先归为风险解释。
2. 包含“搭配、组合、推荐、选型、哪个产品、怎么配、需要哪些产品、能否单独实现”等表达，归为产品选型。
3. 包含“主要功能、功能有哪些、产品介绍、当前能力、更新功能、更新了什么”等表达，归为产品功能介绍。
4. 同时命中多类时按“风险解释 > 产品选型 > 产品功能介绍”的优先级处理。
5. 未命中时使用产品选型框架，保持金融售前产品匹配助手的核心行为。

## 5. 处理流程

1. 现有范围与敏感信息判断先执行。
2. 本地意图分类器返回框架 ID。
3. 现有知识检索返回最多三条证据。
4. 动态提示词明确当前框架的必填、按需和禁止标题。
5. GLM 只根据检索证据生成答案。
6. 动态校验器按框架检查必填标题、禁止标题、重复标题和无证据产品。
7. 校验失败时使用同一框架修复一次，不得在修复时切换框架。
8. 审计日志记录框架 ID、知识 ID、模型和处理状态，不记录密钥。

## 6. 异常与边界

- 分类不明确：回退产品选型框架。
- 功能介绍没有版本对比：说明当前资料能力，不声称“新增”。
- 资料存在冲突：功能介绍增加一次口径说明；风险解释列出冲突点和影响。
- 模型输出了当前框架禁止的标题：修复一次，仍不合格则返回安全校验提示。
- 相同标题重复出现：视为校验失败，防止重复两段风险说明。
- 用户只说“详细说说这部分”且消息中没有可识别对象：当前 V0.1 无长期对话记忆，提示用户补充产品或引用具体内容。

## 7. 测试与验收

自动测试至少覆盖：

- Astro 更新功能问题选择产品功能介绍框架。
- 实时入库与治理搭配问题选择产品选型框架。
- Astro 资产标签资料冲突问题选择风险解释框架。
- 混合问题遵循既定优先级。
- 未知表达回退产品选型框架。
- 三类提示词包含正确标题和禁止规则。
- 三类答案分别通过动态校验。
- 缺少必填标题、出现禁止标题或重复风险标题时校验失败并修复一次。
- 已有产品证据和敏感信息校验继续通过。

企业微信实测至少执行上述三类问题各一条。验收结果应满足：回答框架与意图一致；无重复风险说明；功能介绍问题不强行推荐产品组合；核心产品推荐正确率目标仍不低于 90%。

## 8. Git 与运行边界

- 设计文档、实现和测试分别形成可审查提交。
- 真实 GLM Key、企业微信 Bot ID、Secret 和运行日志不得提交。
- 代码完成并通过本地自动测试后，才重启当前企业微信机器人。
- 重启后继续使用已确认的智谱官方 `glm-5.2` 配置。
