# 金融售前产品助手 V0.1 实施计划

- 日期：2026-09-01
- 依据：`docs/superpowers/specs/2026-09-01-wecom-mvp-runtime-design.md`
- 执行原则：每个任务独立测试、提交并推送 GitHub；真实密钥只在本机输入。

## 任务 1：运行骨架与安全配置

目标：建立可启动、可测试且不泄露密钥的 Node.js/TypeScript 工程。

交付：

- `package.json`、TypeScript 配置和测试命令。
- 环境变量读取与校验模块。
- 无真实值的 `.env.example`。
- `.gitignore` 覆盖密钥、日志、缓存和构建产物。
- 配置模块单元测试。

验收：缺少必要配置时给出明确错误；测试和密钥扫描通过。

## 任务 2：本地知识加载与检索

目标：将现有 CSV 变成可查询的轻量知识库。

交付：

- 产品别名、能力映射和跨产品组合映射加载器。
- 产品名、功能词和场景词规范化。
- 组合规则优先、能力事实补充的 Top 3 检索。
- 来源、审核状态、适用条件和排除条件随结果返回。
- 无结果和待确认知识的安全处理。

验收：200 条模拟问题能够运行确定性映射回归，检索结果可追溯。

## 任务 3：回答规则与模型适配层

目标：接入 Gemini，同时保证未来只改配置即可切换公司模型。

交付：

- OpenAI 兼容聊天客户端接口。
- Gemini 默认配置和可替换模型配置。
- 超时、503 和指数退避重试。
- 基于检索证据的系统提示词。
- 三段式回答解析、格式校验、产品证据校验和安全拒答。
- 模拟模型自动测试及本机 Gemini 冒烟测试脚本。

验收：模拟异常全部覆盖；真实 Gemini 能生成并通过一条三段式答案。

## 任务 4：完整问答管线

目标：把规范化、检索、模型、校验和日志串成一个可单独测试的服务。

交付：

- 单一 `answerQuestion` 用例接口。
- 范围判断、资料不足追问和越界拒答。
- 请求 ID、耗时、命中知识和结果状态日志。
- 本地命令行问答入口，用于不依赖企业微信的快速调试。

验收：正常、模糊、无资料、冲突和模型失败场景均有确定行为。

## 任务 5：企业微信长连接接入

目标：在测试机器人中完成文字消息收发。

交付：

- 企业微信官方 Node.js SDK 接入。
- 单聊和群内 @消息解析。
- 重复消息去重、处理中状态、最终回复和友好错误提示。
- 心跳、断线重连和退出信号处理。
- 使用模拟接入层的自动测试。

验收：本机输入 Bot ID 和 Secret 后能够建立长连接，并在测试群完成一轮问答。

## 任务 6：本机运行与使用说明

目标：让非开发人员能够安全启动、停止和排错。

交付：

- 本机初始化、启动和健康检查脚本。
- 凭证输入说明，不要求将密钥写入仓库。
- 常见错误、日志位置、停止和重启说明。
- Gemini 到公司内网模型的配置切换说明。

验收：从全新克隆到机器人在线的步骤能够重复执行。

## 任务 7：回归、验收与灰度

目标：达到内部测试版上线门槛。

交付：

- 200 条确定性映射回归结果。
- 50 条 Gemini 完整回答测试结果。
- 20 轮企业微信真实问答记录。
- 错题清单、问题修复和最终回归结果。

验收：

- 50 条核心问题至少 45 条完全正确，正确率不低于 90%。
- 三段式格式合格率 100%。
- 资料可追溯率不低于 95%。
- 无资料问题编造率为 0。
- 企业微信消息处理成功率不低于 95%。
- 无 P0 故障或敏感信息泄露。

## 提交顺序

1. `chore: scaffold secure runtime`
2. `feat: add local knowledge retrieval`
3. `feat: add model adapter and answer validation`
4. `feat: add presales question pipeline`
5. `feat: connect wecom long-running bot`
6. `docs: add local runbook and model switching guide`
7. `test: record v0.1 acceptance results`
