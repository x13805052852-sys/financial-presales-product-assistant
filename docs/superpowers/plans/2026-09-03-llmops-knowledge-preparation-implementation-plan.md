# LLMOps 售前知识库首版实施计划

- 日期：2026-09-03
- 对应设计：`../specs/2026-09-03-llmops-knowledge-preparation-design.md`
- 目标：把 LLMOps 资料转成可追溯、可回归测试的首版售前知识，并接入现有本地知识加载器。

## 任务 1：全量资料盘点

- 读取 LLMOps 目录中的 PPTX、PDF、XLSX、图片和视频元数据。
- 记录相对路径、格式、大小、修改时间、页数或幻灯片数、SHA-256 和提取状态。
- 区分当前版、历史版、测试/安全证据和系统元数据文件。

验收：全部文件都有唯一分类；无法提取的文件有明确原因和替代检查方式。

## 任务 2：资料筛选和本地核心资料夹

- 编写资料筛选报告，确定 A/B/C 类证据边界。
- 在原资料目录下创建 `LLMOps首版入库资料`，只复制 5 份 A 类文件。
- 检查复制结果的文件名、数量和哈希。

验收：核心资料夹恰好包含 5 个文件且与来源哈希一致；原始资料不进入 Git。

## 任务 3：产品知识映射

- 建立产品及组件别名表，处理 Agent Go“星将/星构”等版本冲突。
- 建立功能—产品映射，覆盖五个产品域和主要组件。
- 建立场景—组合映射，写清产品分工、适用条件、必须追问、排除条件和来源。

验收：每条映射来源可追溯，历史或规划能力不能标为当前确认能力。

## 任务 4：测试题库

- 生成 100 条 LLMOps 单轮销售问题，覆盖功能介绍、产品选型、组合方案、边界、信息不足和安全问题。
- 生成两轮上下文题，覆盖有效追问、同人换题、跨用户和超时。
- 为每题填写期望产品、期望动作、映射编号、来源和审核状态。

验收：编号唯一、分类平衡、映射全覆盖，核心产品推荐正确率门槛为 90%。

## 任务 5：运行时代码和自动测试

- 扩展知识加载器，使其加载 LLMOps 别名、功能映射和组合映射。
- 扩展产品名词典和检索测试。
- 增加仓库质量测试，校验资料清单、映射和题库结构。
- 运行 TypeScript 类型检查、单元测试、Python 仓库测试和密钥扫描。

验收：新增 LLMOps 问题可命中可审计证据，原有 TDH/跨产品/上下文测试不退化。

## 任务 6：进度和版本管理

- 更新 README、任务跟踪和进度快照。
- 每个可独立验收的阶段形成 Git commit 并推送 GitHub。
- 推送前确认 Git 中不包含公司原始资料、临时渲染文件或凭证。

验收：远端 main 分支包含全部脱敏交付物，工作区只保留明确忽略的本地运行文件。
