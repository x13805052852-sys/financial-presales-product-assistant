# 动态回答框架实施计划

- 日期：2026-09-01
- 对应设计：`../specs/2026-09-01-dynamic-answer-framework-design.md`
- 目标：在不增加模型调用次数的情况下，根据问题意图自动选择回答框架。

## 任务 1：框架类型与本地意图分类

- 新建独立回答框架模块，定义 `product_overview`、`solution_recommendation`、`risk_explanation`。
- 实现确定性中文意图词分类与既定优先级。
- 未命中时回退 `solution_recommendation`。
- 增加单类、混合、大小写和回退测试。

验收：分类不调用模型；设计中的代表问题全部命中预期框架。

## 任务 2：动态提示词

- 为每个框架配置必填、按需和禁止标题。
- `buildGroundedRequest` 接收框架 ID，并生成对应格式说明。
- 功能介绍问题没有版本对比时禁止声称“新增”。
- `buildRepairRequest` 沿用原框架，不允许修复时切换格式。

验收：三类提示词只要求本框架标题，且保留证据约束和密钥安全规则。

## 任务 3：动态答案校验

- `validateAnswer` 按框架检查必填标题。
- 检查禁止标题和重复标题。
- 继续检查检索证据与无依据产品。
- 保持 Markdown 粗体标题兼容。

验收：三类有效答案通过；缺失、越界和重复标题答案失败。

## 任务 4：问答流水线接入

- 范围检查后执行意图分类。
- 将框架传给首次生成、格式修复和答案校验。
- `AnswerResult` 和脱敏审计日志记录框架 ID。
- 不改变无证据、安全拒答和模型错误行为。

验收：同一框架贯穿分类、生成、修复、校验和日志。

## 任务 5：自动回归测试

- 更新现有提示词、校验器和助手测试。
- 新增 Astro 功能介绍、实时治理选型、Astro 资料冲突三类端到端模拟测试。
- 运行 TypeScript 测试、Python 仓库测试、类型检查和构建。
- 执行密钥扫描和 Git diff 检查。

验收：全部自动测试通过，现有 200 条检索回归不退化。

## 任务 6：真实 GLM 与企业微信验证

- 使用当前进程中的安全凭证调用 `glm-5.2`。
- 依次测试功能介绍、选型、风险解释三类问题。
- 确认无重复风险说明，功能介绍不再强行输出组合。
- 更新模型配置说明为当前 `glm-5.2`，不记录真实 Key。

验收：三类真实回答框架正确；企业微信消息成功返回。

## 任务 7：版本提交

- 动态框架实现与测试形成独立提交。
- 企业微信接入代码单独提交，避免混合历史任务。
- 推送 GitHub 并确认远端自动检查通过。
